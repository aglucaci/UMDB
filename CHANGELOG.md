# Changelog

User-visible changes to the UMDB pipeline, data schema and website. Data refreshes from scheduled crawls are not listed individually.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Tagged releases will follow semantic versioning once versioned database releases begin (see [MAINTAINING.md](MAINTAINING.md#releases)).

## [Unreleased]

### Security
- NCBI E-utilities URLs stored for provenance (`debug.runinfo_url`, BioSample `efetch_url`) included the `api_key` and `email` query parameters, so the API key was written to `data/` and published in `docs/db/`. URLs are now stored without them, every JSON writer scrubs them as a safeguard, and `umdb scrub` removes them from existing files. Rotate any key used before this change.

### Added
- **UMDB-SCIENCE research pipeline** (`pipeline/`, Nextflow DSL2; `umdb science`). It tests pre-specified hypotheses on a frozen snapshot of `data/umdb.sqlite`. Track A runs nine catalog-level tests from the database alone: data-quality audit, coverage inequality and blind-spot cities, development, COVID-19 interrupted time series, habitat representation, metadata completeness, centre concentration, technology diffusion, and a blinded expert benchmark of the eligibility screen. It also selects a habitat-, city- and study-balanced shotgun cohort and audits its feasibility. Track B streams that cohort from SRA with a depth cap, runs QC and depth standardization, and profiles species (sylph or MetaPhlAn 4), KEGG orthologs (HUMAnN), resistance genes (KMA/ResFinder) and viral contigs (MEGAHIT/geNomad). Track C runs nine ecology tests on the profiles (habitat vs geography, functional convergence, scaling laws, prediction in held-out cities, air-travel connectivity, cross-habitat connectivity, undiscovered diversity, hemisphere-aligned seasonality, resistome ecology). Each test states its decision rule in advance and reports a status with caveats. A hypothesis registry (`pipeline/assets/hypotheses.csv`) also lists the roadmap. External covariates (GeoNames, World Bank WDI, OpenFlights, optional Köppen–Geiger) are recorded with retrieval dates and checksums. A synthetic fixture with planted effects (`-profile test`) and unit tests cover the statistics. First results on the 2026-11-16 catalog: `manuscript/catalog_findings/`. Research plan: `manuscript/research_program.md`.
- **Validated locations.** Every BioSample's location is resolved at database build time against GeoNames and ISO 3166 (`geo.py`, new tables `countries`, `admin1`, `places`, `sample_locations`; database schema 1.1.0). Each sample gets one accepted country, region and place with a status (verified, probable, ambiguous, conflicting, unresolved), the method and the evidence; the database rejects a place outside its country. Of 406,177 BioSamples, 122,728 have a verified place, 84,134 a probable one, and 3,515 have coordinates that contradict their place name (shown, not mapped). Free-text labels such as "GAZ", "BC" or "Florida (Kennedy Space Center)" no longer appear as cities: 4,855 raw city strings became 2,768 validated places, and 190 raw country strings 148 countries. `umdb geo fetch` downloads the GeoNames extract (14 MB, CC BY 4.0), which is also stored in the catalog bundle; `umdb geo check "USA: Portland, ME"` shows how one string resolves.
- **Exact counts on the website (site schema 3.0.0).** BioSamples and runs are aggregated separately (`samples.json`, `cube.json`) with set-valued project and assay dimensions, so a sample with several runs, assays or studies is counted once; totals are tested against SQLite. `geo.json` publishes the validated hierarchy; `summary.json` labels every count with its unit and adds collection years and location status.
- **New Explorer.** Cascading country → region → city filters with counts that only offer combinations that exist, location-quality, environment, assay, collection-year and release-year filters, all kept in the page address; Studies, BioSamples and Runs views; a study drawer showing each sample's accepted location next to the submitted text; suggestions when no record matches; cohort export (runs TSV, accession list, and a query manifest recording the release, filters and expected counts).
- **New Map (MapLibre).** Country coverage from validated countries, clustered reported sampling sites, and an environment view; clicking a country lists its regions and cities and links to the same selection in the Explorer. A table repeats the map's numbers for keyboard and screen-reader use. Zooming in fades the country shading into an OpenStreetMap street map (OpenFreeMap, no API key), and choosing a city zooms to street level; reported coordinates are published at 0.01° (about 1 km). Russia and Fiji, which cross the 180° meridian, no longer draw as bands across the map.
- Batched, concurrent NCBI fetching. RunInfo and BioSample records are fetched 200 per request, BioProjects and per-profile searches in parallel, under one shared rate limiter (`UMDB_NCBI_RPS`, default 8/s with a key, slowed automatically on HTTP 429; `UMDB_NCBI_WORKERS`, default 6). A day of 1,268 experiments went from 11 min 27 s (about 2,600 requests) to 17 s (66 requests) in testing, with identical records. EBI `SAMEA` BioSamples, which efetch cannot return by accession, are resolved to UIDs by batched search, so their metadata is now filled in; previously they were cached empty (23,113 of 26,936 cached SAMEA samples had no attributes, so their location, environment and eligibility came only from run titles).
- `backfill-year --window day|week|month|auto`: release-date span per search. `auto` (default) searches a month at a time when there is no per-day cap, so a year takes 84 searches instead of 2,555; results are identical.
- BioProjects are fetched in batches too: one esearch per 50 accessions and one esummary per 200 projects (150 projects: 4 requests, 2.5 s). After an HTTP 429 the request rate drops, then recovers 10% every 10 s after a minute without one.
- Compact website data (site schema 2.0.0). Instead of every run record (over 1 GB in `docs/db/`), the site loads `summary.json`, `cube.json` (runs aggregated by project, year, place, assay, tier, context, AI review and rounded coordinates: 11,746 rows for 245,903 runs) and `projects.json`, about 0.4 MB compressed, and fetches `p/<ACC>.json` when a project is opened or exported. Explorer filters, analytics and the map work unchanged. Built from the SQLite database by `site.py` (`umdb export`, and after every harvest); unchanged files are not rewritten.
- The harvested catalog moves to GitHub Release assets: `umdb catalog push|pull|status`. `data/srr_catalog_*.jsonl`, `data/cache/*.json` and `data/seen_*.txt` are git-ignored and uploaded as one gzipped bundle with SHA-256 checksums to the `catalog-latest` release (1.2 GB packs to 65 MB); `--snapshot` adds a dated release. A push is refused if someone else pushed since your last pull; `pull --merge` combines them. Both workflows pull before and push after.
- `umdb repair` (`repair-bioprojects`): re-fetch cached BioProjects stored under the wrong accession; run `umdb export` and `umdb db build` afterwards.
- `umdb scrub` (`scrub-secrets`): remove `api_key=`/`email=` from stored URLs in `data/`, `docs/` and `logs/`.
- SQLite query database `data/umdb.sqlite` (schema 1.0.0), derived from the git JSONL catalog and caches: normalized `projects` / `samples` / `experiments` / `runs` / `project_samples` / `ai_annotations` tables with BioSample as the unit of observation, cohort and foreign-key indexes, an FTS5 full-text index, and `umdb_samples` / `umdb_runs` views. Built in about 30 s by `umdb db build`, and automatically after every harvest (`--no-db` skips it). Query with `umdb db info|shell|query`.
- Versioned releases: `umdb release` writes Parquet tables (Zstandard, typed columns, NULL for unknown), gzipped TSV, `schema.json`, `manifest.json` and `checksums.sha256` to `dist/releases/<version>/`. The whole catalog is about 11 MB, versus 243 MB of website JSON. Optional dependency: `requirements-release.txt` (pyarrow, duckdb).
- `ARCHITECTURE.md`: data flow, schema, example SQL and DuckDB queries, release process.
- Verbose, colour-coded output for every command: startup settings and catalog state, per-day/per-page hits, ingest progress with ETA, export steps with eligibility tiers, a closing summary with NCBI request statistics, and retry and failure warnings. `-v`/`--verbose` adds every request and cache hit; `-q`/`--quiet` shows summaries only (`UMDB_VERBOSITY`, `NO_COLOR`, `UMDB_COLOR`). Backfill logs stay plain text.
- Deepest-search mode: `umdb deepest` (= `scripts/deep_backfill.sh --deepest`) harvests 2007 to now year by year with every profile, paging through every hit per day (`--max-per-day 0`, now the default). It re-fetches records already held (`--refresh` on `crawl`, `daily` and `backfill-year`) and compacts the catalog after each year (`umdb compact`), keeping only the newest record per run. Exports publish only the newest record per run. Refresh and compaction ask before overwriting uncommitted data.
- `umdb` command (`bin/umdb`, install with `bin/umdb install`): `umdb crawl|daily|backfill-year|curate-ai` (or `umdb run …`), `umdb backfill`, `export`, `serve`, `status`, `queries`, `test`. Prints an ASCII-art banner in interactive terminals (`UMDB_NO_BANNER=1` hides it).
- Sample-level urban eligibility screen (`eligibility.py`), following a staged model: environmental eligibility, then urban-origin verification, then annotation. Every run gets `eligibility.status` (`confirmed_urban` / `probable_urban` / `uncertain` / `non_urban` / `non_environmental`), an urban context category, location resolution, and structured evidence (source, field, value, signal). Uses `building_setting` and `built_struc_set` when present. A city name alone gives at most `probable_urban`. Tier counts are in `summary.json`, and the explorer has an **Urban eligibility** filter and a per-run label. Current catalog: 3,362 confirmed, 17,209 probable, 18,232 uncertain, 2,093 non-urban and 19,025 non-environmental runs. No records are removed.
- `scripts/deep_backfill.sh`: resumable year-by-year harvest with every profile at NCBI's 10,000-per-day maximum, per-year logs and completion markers, optional per-year commits.
- `backfill-year` warns when a day/profile search hits `--max-per-day`.
- `INCLUSION_CRITERIA.md`: how records are selected as urban (keyword search only), exact queries, measured composition, filtering recipes. Linked from the README, the methodology page and the curation docs.
- `LICENSE`: CC BY-NC-SA 4.0 for code, documentation, annotations and data; declared in `CITATION.cff` and the README.
- `CONTRIBUTING.md`, `MAINTAINING.md`, `DATA_DICTIONARY.md`, `CURATION.md`, `SECURITY.md`, `CITATION.cff`, issue and pull request templates.
- Settings file support: the harvester loads a git-ignored `.env` from the repository root; template in `.env.example`. Shell variables and CI secrets take precedence.
- Offline unit tests (`tests/`), run with `python3 -m unittest discover tests`.
- `QUERY_PROFILES_VERSION`, recorded in `docs/debug/latest_report.json` with each run.
- New `geo` fields: `raw_field`, `country_source`, `city_status`, `locality_tokens`, `parse_flags`, `resolution`, `collection_date`.
- New assay classes `Metatranscriptomics` and `Viral RNA`, plus `18S`.

### Changed
- Slim run records: the BioProject description and raw esummary fields are stored once per project (`bioprojects.json`), not on every run, and the 47 RunInfo column names are no longer repeated. BioProject evidence in `eligibility` keeps terms, not text. New harvests write slim records, exports publish them, and `umdb compact` slims `data/`. Current catalog: run files 230 → 152 MB; published run parts 481 → 243 MB (5 files instead of 10), including the double-count fix. The eligibility screen still reads full project text from the cache.
- Discovery queries rewritten (`QUERY_PROFILES_VERSION` 2026.11.2): seven urban-environment profiles (`municipal_wastewater`, `air_dust`, `built_environment`, `urban_metagenome`, `transit`, `urban_soil_greenspace`, `urban_water_drainage`) built on NCBI environment organism labels and urban phrases, with no catch-all terms and no global NOT block. SARS-CoV-2 targeted amplicon surveillance is the opt-in `wastewater_sars_cov_2` profile. 2025 matches drop from roughly 600,000+ to 64,173 experiments, while 98% of 2024 confirmed-urban and 95% of probable-urban catalog runs are still found, and 99.5% of non-environmental runs no longer match. The old profiles remain as `LEGACY_QUERY_PROFILES`.
- Eligibility screen: "X City" place names no longer count as explicit urban wording (rules 2026.11.6).
- Renamed the harvester package `scripts/urbanscope_harvester` → `scripts/umdb_harvester`, the workflows to `umdb_*.yml`, and the NCBI tool name to `umdb-srr-harvester`. Older harvested records still contain `tool=urbanscope-srr-harvester` in their stored request URLs.
- Exports now re-derive `geo` and `assay` for every record from cached metadata, so rule fixes apply to the whole catalog.
- Assay classification trusts `LibraryStrategy` and `LibrarySource` before free text.
- Geography parsing classifies tokens instead of taking the last comma-separated token as the city. Effect on the catalog's 59,921 unique runs: runs with a country and city 26,209 → 20,128; distinct city labels 1,407 → 1,155. The removed values were states, counties, continents and placeholders.
- Manifest field `years` renamed to `catalog_file_years` (it lists harvest-file years, not run release years).
- Discovery queries no longer exclude soil, sediment, freshwater, river, lake or "plant".

### Fixed
- Location inference from coordinates alone assigned the most populous settlement within 15 km even when the sample was not in it: 2,999 Danish samples labelled only "Denmark" became the village of Bælum (702 people), samples from the Barro Colorado Island rainforest station became the village of Escobal, and "Norfolk County" (a county) appeared as a city. A place is now inferred only when the coordinates fall within its population-scaled extent, and never for administrative-unit names (location rules 2026.11.2); about 9,800 samples now keep their country without a city. Analytics shows exact per-place counts by GeoNames id ("Top Places").
- Website BioSample counts no longer double-count: the old cube summed per-group sample counts, so a sample with runs in two assays or studies was counted twice in Explorer and Map totals.
- Country and city tallies in `summary.json` preferred AI-proposed values while filters used rule-based ones, so the two could disagree after an AI review. AI proposals are now shown as proposals only; every count and filter uses the validated location.
- Project titles and other submitter text on the Analytics page are escaped before insertion into the page.
- After a harvest, the export and database build read the BioSample/BioProject caches from disk before the run had saved its new entries, so newly fetched samples were annotated without their metadata until the next run. Caches are now saved first.
- Both workflows called `python3 -m scripts.umdb_harvester.cli`, which never ran a harvest; they now call `python3 -m scripts.umdb_harvester`.
- BioProject lookups took the first `[Accession]` search hit, which can be a different project that links to the requested one (PRJNA293225 was stored as PRJDB9202). 232 of 5,749 cached projects were affected. Lookups now match the exact accession, and exports and the database take project fields from the corrected cache.
- NCBI requests on networks that inspect HTTPS: a certificate error now retries once with the macOS System keychain roots (still verified), `UMDB_CA_BUNDLE` adds a custom root, and persistent certificate errors stop immediately with instructions instead of retrying. `umdb backfill` / `deepest` stop when a TLS error or two consecutive failed years would make every remaining year fail.
- **Run counts were inflated by 78%.** Exports read every `srr_catalog_<YEAR>_partNNN.jsonl` file twice (the year glob matched the part files, which were then read again through the base file). The April 2026 release reported 106,558 runs; the catalog holds **59,921 unique runs**. Run-level counts (runs, assay, country, city and year tallies) were affected; BioSample and BioProject counts were not. Exports now return one base path per year and never emit a run twice.
- `backfill-year` and `daily` never returned any records: they searched SRA with `datetype=edat`, which SRA ignores, and `backfill-year` sent ISO `YYYY-MM-DD` dates, which return nothing. Both now use `pdat` (public release date) with `YYYY/MM/DD`. Until this fix only `crawl` had ever harvested data.
- esummary now covers every UID in batches of 200. It previously stopped at the first 500 of up to 2,500 per page.
- SRA experiment titles are read from `ExpXml`. Every record harvested before this fix has an empty `title`.
- "plant" in the exclusion list silently dropped wastewater treatment plant studies.
- The English word "its" (and words like "sites") no longer triggers the ITS class.
- The country fallback no longer matches aliases inside words (e.g. "uk" in "Fukuoka").

### Known issues
- AI-reviewed values override rule values even when unchanged, so older reviews can re-introduce pre-fix city values.
